# scripts —— 可复跑的验证工具

这些脚本不是示例，是**报数之前必须跑一遍**的关卡。原因见 `../SKILL.md` §3：
我曾在追迹器有静默 bug 的情况下连续交付了三轮错误数据；
2026-10-18 又发现**本目录自己的关卡就带着两处数据/符号错误在裸奔**（见下）。

## 关卡 1：追迹器 + 近轴引擎（必跑）

```bash
python check_design_gates.py          # 推荐：全套六道检查
```

从本目录运行（脚本之间互相 import）。六道检查：

- **A 追迹器 vs 朴素独立实现**：Zemax 样板双胶合上，`tracer.py` 与 `naive_ref.py`
  （手写、只共享玻璃目录数据）须在 1e-4…1.0 光瞳高度逐点吻合到 **< 1e-6 mm**。
- **B 小孔径线性**：y/光瞳在 1e-5…1e-3 恒定到 1e-9。
- **C 已知单透镜**：N-BK7 平凸 R=20（f = R/(n-1) = 38.59 mm，555 nm）。
- **D 精确对焦**：像距取近轴 l′（march 的 bfd），h=0.05 光线必须落在轴上 |y|<1e-4。
  这是抓**近轴传递符号错误**的决定性关卡（2026-10-18：错号把 100 mm 算成 183/192 mm）。
- **E 已知答案的第三条路**：2×2 矩阵法（`matrix_firstorder.py`）与 march 的
  EFL/l′ 必须在 1e-6 内一致，且等于 **100.0439 / 97.9387**。
  **A/B 只比较两个实现，喂同一份错数据它们会一起错着通过**——本目录就犯过：
  `naive_ref.py` 和旧关卡把双胶合末面曲率符号写反（+0.007677），A/B 照样 PASS，
  而那套系统其实是近无焦的（EFL ≈ −19 m）。所以必须有 E 这种"答案来自文件之外"的关卡。
- **F 凹面**：强凹面弯月镜（c2 = −1/12）必须能追迹并对焦。
  顶点平面推进遇到凹面时交点在**微负 t**；只取 t≥0 的追迹器在这里直接 miss。

老的 `check_tracer.py` 仍然可用（它只含双胶合一处已知答案，且自带法向近似/精确对照）。

## 关卡 2：.zmx 结构

```bash
python check_zmx_structure.py 我的镜头.zmx
python check_zmx_structure.py 我的镜头.zmx 参考文件.zmx
```

**检查项**：
- 编码必须是 **UTF-16 LE + BOM**（Zemax 在 Windows 上的写法）
- 顶层关键字：`missing` 必须为 `none`
- 表面块关键字：`missing` 里若出现 `COAT`/`FLAP`/`VDSZ` 等**可选**字段，无害；
  但 `CURV`/`DISZ`/`GLAS`/`STOP`/`TYPE`/`SSID` 缺了必有问题
- 内容断言：`ENPD`、`GCAT`、`YFLN`、`FTYP`、≥3 个 `WAVM`、`PWAV`、`SURF 0`

**注意**：结构比对通过 ≠ 文件正确。格式对但处方错、玻璃占位、变量没标记，
这些问题它看不出来。**结构校验是必要条件，不是充分条件。**

## 关卡 3：通光口径 / 暗角检查（新，必跑）

```bash
python footprints.py 我的镜头.zmx
```

把文件里写的 `DIAM`（**是清晰半直径，不是直径**——样板双胶合可证：ENPD 10 → 光阑
DIAM 5）与按 ENPD+视场追出来的**光束半高**逐面对比，写小了就报 VIGNETTING。
2026-10-18 的用户文件名义 f/4.5，实际多个面口径只有光束的 60–70%，轴上挡到约 f/4.7、
视场边缘挡得更多——文件层面毫无报错。

## 关卡 4：交付文件的反解析复算（必跑）

生成 `.zmx` 之后，**从文件本身**把处方读回来再追一遍——别复用生成时的内存数据。

## 模块速查

| 文件 | 作用 |
|---|---|
| `glass_index.py` | 从 `SCHOTT.AGF` 读 Sellmeier 系数（**CD 行是交错列 B1 C1 B2 C2 B3 C3**，每条都对照 NM 行的 nd/vd 自检） |
| `paraxial.py` | 独立近轴 y-u 引擎（EFL/BFD/像高）。**EFL 不能用 1/Σφ**（只对接触的薄元成立），要用 march |
| `matrix_firstorder.py` | 2×2 矩阵一阶量（EFL/l′），第三条独立路径 |
| `tracer.py` | 纯标量真实光线追迹（球面、牛顿求交、正确法向），带 `spot()` |
| `naive_ref.py` | 双胶合的朴素独立实现，只做关卡 A 的对照 |
| `footprints.py` | 暗角/口径检查（关卡 3） |
| `check_design_gates.py` | 六道关卡（A–F） |
| `check_tracer.py` | 旧关卡：双胶合 + 近似法向对照 |
| `check_zmx_structure.py` | .zmx 结构比对 |

## 已知正确基准（2026-10-18 三条独立路径一致）

| 量 | 值 | 来源 |
|---|---|---|
| 双胶合 EFL（0.633 µm） | **100.0439 mm** | march / 矩阵法 / 实追对焦扫描，三者一致 |
| 双胶合近轴 l′（末面到焦点） | **97.9387 mm** | 同上 |
| 双胶合文件自带 BFD | 98.475961 mm | 样本文件原值（比近轴焦点远 0.54 mm，属设计者选择） |

> 旧版脚本打印的 "99.0439" 来自一个**传递符号写反的近轴**（y − t·u），错 1%。
> 它作为"独立参照"印在关卡里多年——连参照本身都可能是错的，所以必须三角互验。

## 建议的使用顺序

```
1. 改完追迹器/近轴引擎   → python check_design_gates.py
2. 写完 .zmx            → python check_zmx_structure.py 我的.zmx
3. 交付前                → python footprints.py 我的.zmx
4. 报数给用户之前        → 从文件反解析、用关卡里的追迹器复算 EFL / 色差 / 点列
```

第 4 步的"从文件读回"是硬要求：**生成脚本与验算脚本不能共用内存数据**，
否则同一个 bug 会同时污染两边，两边一致地给出错误答案。
